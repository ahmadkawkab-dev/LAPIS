# UI/UX audit — October 2026

The repository implementation is the source of truth. This inventory covers the signed-in shell, public authentication, Boards, Tasks, Calendar, Account, shared controls, development previews, responsive styles, and the frontend API boundary. Priorities: P0 is misleading or inaccessible, P1 is a significant usability problem, and P2 is refinement. KEEP, IMPROVE, CONSOLIDATE, MOVE, and REMOVE describe the decision; they do not imply deleting domain behavior.

| Area | Decision | Problem and evidence | Principle | Change and risk |
| --- | --- | --- | --- | --- |
| Global / public auth | KEEP | `AuthScreen`, public pages, loading, and signed-out routes have distinct goals and working actions. | Preserve user control | Keep authentication behavior and recovery paths; changing it risks sign-in. |
| Navigation | P1 IMPROVE | Sidebar and mobile nav gave Library, Pictures, and Journal “Soon” entries equal prominence with working routes. Mobile also repeated Account in the header and bottom nav. | Recognition; honest affordances | Show Boards, Tasks, Calendar in primary nav; keep upcoming routes and dev previews. Account remains available from the header on mobile and sidebar on desktop. Risk: users of direct upcoming URLs still need them to resolve. |
| Board landing | P1 IMPROVE | Greeting, helper lines, section descriptions, role phrases, member count, and arrow repeated the page or card context. Card wrapper and inner link both carried card styling. | Minimal presentation; hierarchy | Use a clear Boards heading, compact section headings, one visible card surface, title, content counts/progress, shared permission, and recency. Keep search, create, empty/error states, and visible owner actions. Risk: do not hide permission or owner actions. |
| Board workspace | P0 REMOVE | `BoardWorkspace` exposed Chat, but the only handler opened a panel announcing chat was unavailable; there was no chat API or composer. | Status and real-world expectations | Remove that control, panel, and state branch. Keep notes, checklists, canvas, sharing, presence, connections, and realtime behavior untouched. |
| Board canvas / sharing | KEEP | The canvas, inspector, Tasks panel, Share panel, member menu, zoom, and presence have distinct jobs. Owner actions are visible on board cards and available with Shift+F10 in the sidebar. | Recognition and user control | Retain each path. Do not collapse board checklists into personal tasks or alter gesture, geometry, permission, or draft behavior. |
| Tasks | P1 IMPROVE | Weekly day menus and inline add forms removed the focused control on close; template icon targets were 32px. Repeated eyebrow/helper copy competed with the week. | Predictable focus; target size | Return focus to the trigger, enlarge compact action targets, and trim repeated copy. Preserve week, Quick Tasks, views, lists, templates, date/time, and drag plus form scheduling. Risk: templates and keyboard flows. |
| Calendar | P2 IMPROVE | A permanent footnote restated the task/event distinction already shown in agenda labels and item styling; month item controls could be under 24px tall. | Scanability; target size | Remove the footnote and set a 24px minimum for dense month entries. Keep Month/Agenda, event editing, tray, and date picker as a drag alternative. Risk: month density. |
| Account | P1 CONSOLIDATE | Profile repeated the avatar and identity above its editable photo row. The back control duplicated app navigation, section headings skipped from h1 to h3, and one generic profile error could offer a reload after a failed save. | Avoid repetition; semantic hierarchy; preserve user input | Keep one photo row, use h2 section headings, and offer profile reload only for a load failure. Preserve profile, theme, Google link, session actions, and legal links. |
| Responsive | P1 IMPROVE | Five bottom destinations compressed mobile navigation; three were working product areas. Tasks uses a horizontal view/list strip and Calendar defaults to Agenda on narrow widths. | Prioritize the current task | Use three equally sized mobile destinations. Retain the existing task strip, calendar tray, and board mobile inspector pending live-device review. Risk: small-width overflow. |
| Accessibility | P1 IMPROVE | Mobile Boards lacked `aria-current`; the board card used a button with block and heading descendants, and its `aria-label` hid card details. | Semantics and keyboard access | Use a real board link with a heading and concise description; add current-page semantics and focus restoration. Keep native dialog focus management and visible focus styles. Risk: click interception must preserve modified-click link behavior. |
| Shared components | P1 IMPROVE | The render error boundary displayed raw `error.message`, which may contain implementation details and no useful recovery instruction. Buttons, fields, dialog, notice, and theme control already share patterns. | Plain-language error recovery | Show a stable explanation with Reload Wukna; keep console diagnostics. Keep the shared primitives and inline API/form errors. |
| Design system / CSS | P2 CONSOLIDATE | Semantic color, spacing, type, target, motion, and layer tokens exist; a few removed UI elements left selectors in feature CSS. Legacy board CSS deliberately coexists with newer overrides. | Consistency without broad refactoring | Reuse tokens and remove selectors only when references are traced. A broad legacy CSS deletion would risk board geometry and responsive behavior. |

The same visual language should make page location, primary action, current status, and recovery clear before decoration. Product data and collaboration state remain more prominent than chrome. Secondary actions may be quiet, but must remain discoverable and keyboard reachable. This applies the repository's [design system](UI_UX_DESIGN_SYSTEM.md) alongside [Nielsen Norman Group's usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/), [WCAG 2.2 target sizing](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum), [drag alternatives](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements), the [ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), and [Apple's feedback guidance](https://developer.apple.com/design/human-interface-guidelines/feedback).

## Verification boundary

On October 2, `dotnet restore`, `dotnet build`, the PostgreSQL integration suite (55 tests), `npm ci`, `npm run typecheck`, `npm test` (16 test files), `npm run build`, and `git diff --check` passed. An isolated PostgreSQL QA instance received every migration. A local headless browser completed registration and sign-in, profile save and reload, task creation and reminder scheduling, upcoming notification display, template creation and server search, and calendar event creation and reload. The profile and preferences screens were inspected at desktop and mobile widths. The narrow weekly day card was checked for field and button overlap in light and dark themes; browser flows verified right-click edit and delete for week tasks, calendar tasks, and events, plus confirmed Clear day. No page errors appeared in the tested signed-in flows. These checks do not replace a screen-reader audit, a touch-device gesture pass, or production smoke testing.

Static contrast checks of the semantic muted text on both main surfaces and primary text on selected surfaces yielded 5.03:1–9.13:1 across light and dark themes. This is a token check, not a complete contrast audit of every dynamic note pigment, image, hover state, or third-party browser rendering.
